1. 이번 추가 요청 반영

  • 솔라피 개인 계정·인증 발신번호·IP 한 곳으로 제한한 API 키를 연결했습니다. 구매자의 거래 약속에서 생성된 시험 문자 1건이 공급자 성공 처리되고 본인 휴대폰에 수신됐음을 확인했습니다.
  • 시험 발송은 무료 포인트 300P 중 45P를 사용했습니다. 확인 시 잔여 255P, 유료 충전 0원, 자동충전 꺼짐입니다. 서비스 단가와 잔액은 이후 변할 수 있습니다.
  • 문자 API 키 만료일은 2026-12-04입니다. 이 컴퓨터의 지정 IP에서 사용하도록 제한했으므로 실행 장소/IP가 바뀌면 허용 IP를 확인해야 합니다. 실제 키와 발신번호는 ZIP에 넣지 않습니다.
  • 네이버 발송용 앱 비밀번호를 ZIP 외부의 비공개 설정에 연결했습니다. 실제 메일 서버 인증과 아이디 찾기·비밀번호 재설정·거래 약속 이메일 수신을 확인했습니다.
  • Spring Security를 적용했습니다. 학생·사장·매니저·관리자 로그인 구분과 같은 사이트 내 로그인 유지를 보존하고, 계정 변경 요청의 세션별 CSRF 검사 및 동일 계정·접속지의 10분 내 5회 실패 제한을 추가했습니다.
  • 기존 전체 기능과 새 보안 검사를 포함한 Java 테스트 85개가 통과했습니다. 실제 회원 비밀번호를 바꾸지 않고 별도 메모리 DB의 시험 계정으로 재설정과 이전 로그인 차단을 검증했습니다.
  • 상품 상세의 좋아요를 하단에서 사진 위 상단 오른쪽으로 옮겼습니다. 닫기(X) 왼쪽에 좋아요·개수를 나란히 표시하고, 기존 하단 버튼은 제거했습니다. 목록 하트와 같은 좋아요 기록을 사용합니다.
  • 커뮤니티 왼쪽 이야기 카테고리 아이콘을 제거하고 카테고리명·게시글 수만 표시합니다.
  • 카카오 REST API 키를 비공개 설정으로 연결하고 카카오맵 API를 활성화했습니다. 도로명 3곳·지번 1곳의 실제 주소→좌표 변환 및 회원가입 지도 핀 이동을 검증했습니다. 상세는 00_카카오API_연결완료.md에 기록했습니다.
  • 학교생활의 캠퍼스 카페(예시)를 삭제했습니다. 목록·지도·공개 가게 좋아요 대상에서 제외되며, 새 실행 때도 초기 데이터로 생성하지 않습니다.
  • 실제 가게 세 곳은 유지합니다: 이태리부대찌개 인하대역점 / 고수찜닭 본점 / 양궈푸마라탕 인하대점.
  • 가게마다 지도에서 보기 + 좋아요를 한 줄에 나란히 배치했습니다. 지도 버튼은 위치 아이콘과 초록 배경, 좋아요는 하트와 연분홍 계열로 꾸미고 높이·간격·포커스를 통일했습니다.
  • 커뮤니티 목록의 좋아요를 게시글 아래 별도 줄에서 빼서 댓글 수 바로 옆으로 옮겼습니다. 댓글·좋아요가 같은 줄에 표시되고, 좋아요를 눌러도 게시글이 함께 열리지 않습니다.
  • 상품 목록의 판매자 박스를 제거했습니다. 목록에는 상품 정보와 사진 우측 상단 하트가 표시됩니다.
  • 상품을 클릭한 상세 화면에 판매자 정보 카드를 구성했습니다: 프로필 아이콘 / 이름 / 학교 / 매너온도 / 평균 별점 / 후기 수 / 완료 거래 수 / 만족 후기 비율 / 실제로 받은 칭찬 키워드 / 판매자 정보·판매글 더보기.
  • 별점·만족도·후기·칭찬 수는 실제 거래 평가를 집계합니다. 후기가 없으면 평가 전·빈 상태로 표시하며, 임의의 4.9점·96%·후기 수를 넣지 않습니다. 칭찬 키워드는 정해진 태도 항목만 합산하고 자유 입력 후기 본문은 공개하지 않습니다.
  • 시연판매자 A·B·C 계정을 준비했습니다. 새 DB의 예시 판매글은 처음부터 구분합니다. 현재 공유 DB는 기존 거래가 연결된 A의 글은 유지하고 거래가 없는 기존 예시 글만 B/C에 나누어 배정했습니다. 신규 사용자 글이나 거래·평가의 소유자는 바꾸지 않습니다.
  • 로그인·회원가입 화면 상단의 학생 페이지 / 중고거래 버튼을 제거했습니다. 브랜드 로고, 로그인·가입 폼, 아이디 찾기·비밀번호 변경 기능은 유지합니다.

2. 회의록 1~9번 반영 내역

1) 학생 페이지 좋아요 UI

  • 관심목록과 좋아요를 한 기능으로 통합했습니다.
  • 중고거래 사진 우측 상단에 흰 테두리 하트를 표시하고, 선택 시 붉은 하트로 바뀝니다.
  • 좋아요 개수·취소·로그인 안내·저장 결과를 화면에 반영합니다.

2) 사장님 주소·위도·경도

  • 회원가입 주소 검색·상세 주소·지도 위치 확인과 좌표 저장을 연결했습니다.
  • 좌표를 DB에 저장해 학생 페이지 학교생활 지도에 실제 가게 위치를 표시합니다.
  • 사장센터에서 주소·지도 위치를 다시 수정할 수 있습니다.
  • 좌표 유효 범위와 위도·경도 쌍을 검증합니다.
  • 현재 공유 서버에서 카카오 주소 자동 변환을 실제 연결했습니다. 주소 선택 또는 주소로 위치 찾기 후 지도 핀과 좌표가 자동으로 채워집니다. 지도 직접 보정도 유지합니다. 다른 컴퓨터에서 새로 실행할 때는 본인의 REST API 키를 config/local.env.cmd의 KAKAO_REST_API_KEY에 설정해야 합니다.

3) 사장님 학교 선택

  • 기존 학교 목록을 불러와 사장님 가입 시 선택하도록 했습니다.
  • 기존 학교 테이블의 학교 ID를 회원 정보에 연결합니다.

4) 학교생활 가게 사진

  • 사장님 가입·가게 정보와 사진 업로드 데이터를 연결했습니다.
  • 등록된 사진이 있으면 목록과 상세에 실제 사진을 표시하고, 없으면 대체 아이콘을 사용합니다.
  • 참고 지도 화면의 사진을 무단으로 내려받아 채워 넣지는 않았습니다. 현재 세 업체에 사진이 등록되지 않았다면 아이콘이 보입니다.

5) 아이디 찾기·비밀번호 변경

  • 로그인 화면에 아이디 찾기·비밀번호 변경 기능과 이메일 인증 흐름을 추가했습니다.
  • 무료 로컬 시험 모드에서는 앱의 시험 수신함으로 인증 메일을 확인할 수 있습니다.
  • 현재 공유 서버는 네이버 SMTP를 연결해 실제 인증메일을 발송합니다. 받은메일함 수신 후 해당 인증번호로 아이디 찾기·비밀번호 재설정을 끝까지 확인했습니다.
  • 인증번호 5분 유효·5회 실패 제한·재요청 1분 간격·사용 후 재사용 차단을 적용했습니다. 재설정 후 이전 비밀번호와 기존 로그인 세션을 차단합니다.
  • ZIP에는 발신 비밀번호를 넣지 않습니다. 다른 컴퓨터의 실행은 config/local.env.example.cmd를 복사해 본인의 발신 설정을 입력해야 합니다.

6) 검색어 전체 삭제

  • 물품·게시글 등 검색 입력에 X 삭제 버튼을 추가했습니다.
  • 버튼을 누르면 검색어를 한 번에 지우고 목록을 갱신합니다.

7) 공통 버튼 UI

  • 로그인·회원가입·콘텐츠 추가 버튼과 페이지 이동 버튼의 모양·간격·아이콘을 정리했습니다.
  • 최신 요청에 따라 로그인·가입 화면의 별도 학생 페이지/중고거래 이동 버튼은 제거했습니다.

8) 좋아요 통합

  • 판매글·일반 게시글·가게·댓글에 서버 저장형 좋아요를 적용했습니다.
  • 계정별 콘텐츠 한 개당 좋아요 한 개, 중복 방지·취소·새로고침 유지가 가능합니다.
  • 예전 관심 등록과 좋아요 기록은 중복 없이 통합하고 기존 관심 API는 호환 경로로 유지했습니다.
  • 상단 ♡ 좋아요 메뉴에서 본인이 좋아요한 판매글·가게·글·댓글을 모아 봅니다.
  • 좋아요 목록은 본인만 확인합니다. 콘텐츠의 좋아요와 거래 평가의 ‘좋아요’는 별개이며, 하트를 눌러도 매너온도가 오르지 않습니다.
  • 판매 물품 가격 변동 알림은 회의록의 추후 검토 항목으로 남아 있습니다.

9) 거래 약속 알림

  • 구매자가 거래 약속을 만들면 판매자에게 앱 내부 알림을 저장하고 표시합니다.
  • 판매자 계정에 알림이 연결되며 미확인 수·목록을 확인할 수 있습니다.
  • 이메일은 실제 네이버 SMTP로 연결했습니다. 구매자 약속 생성 → 판매자 알림 저장 → 이메일 서비스 접수 → 받은메일함의 상품·시간·장소·금액 확인까지 검증했습니다.
  • 성공한 발송을 재시도로 중복 발송하지 않도록 기존 동작을 유지합니다. 발송 상태의 ‘서비스 접수 완료’는 일반적인 모든 수신자의 배달 보증을 뜻하지 않습니다.
  • 문자는 실제 솔라피 계정을 연결했습니다. 별도 시험 DB에서 구매자 예약 → 판매자 문자 접수 → 공급자 성공 1건/실패 0건 → 본인 휴대폰 수신까지 확인했습니다. 공유 서버에도 같은 비공개 설정을 연결했습니다.
  • 기존 과거 대기 알림이 한꺼번에 발송되지 않게 확인하고 반영했습니다(반영 시 과거 대기 0건). 시험 문자를 자동으로 반복 발송하지 않았습니다.
  • 알림톡 연동 코드와 모의 검사는 유지합니다. 사용자에게 사업자등록증/단체 고유번호증이 없어 비즈니스 채널 인증과 실제 알림톡 발송은 완료하지 않았습니다. 별도 유료 충전은 진행하지 않았습니다.
  • 무료 시험 실행 명령은 외부 발송 없이 로컬 수신함/앱 내부 알림을 사용합니다. 현재 공유 서버의 실제 이메일 연결과는 구분됩니다.

3. 게시판·댓글 추가 개발

  • 커뮤니티를 카테고리·검색·게시글 목록·상세·작성·댓글 구조로 개선했습니다.
  • 게시글과 댓글을 서버 DB에 저장하고 실제 로그인 회원과 연결합니다.
  • 작성자 본인만 글 수정·삭제 및 본인 댓글 삭제를 수행합니다.
  • 입력 검증, 권한 확인, CSRF 확인을 적용했습니다.
  • 게시글별 댓글 수와 좋아요를 목록 하단 같은 줄에 표시합니다.

4. 로그인·역할·페이지 이동

  • 로그인에서 학생 학교 선택과 사장님·매니저·관리자 유형을 구분합니다.
  • 사장님·매니저·관리자는 아이디로, 학생은 학교와 학번으로 로그인합니다.
  • 학생 사이트에서 로그인하면 학생 사이트를 이용하고, 사장센터에서는 사장센터를 이용합니다. 같은 주소의 학생 사이트·사장센터·관리자 페이지는 세션을 공유해 다시 로그인하지 않고 이동합니다.
  • 사장·매니저·관리자 권한을 서버에서 검사합니다.
  • 별도 매니저 관리 독립 화면은 기존 요청에 따라 제거하고 호환 이동 처리를 유지했습니다.
  • 매니저 운영 권한과 사장님의 가게 정보·매니저 관리 권한은 구분합니다.
  • Spring Security의 인증·인가 필터에서 현재 DB의 회원 역할을 확인합니다. 삭제한 매니저와 비밀번호 재설정으로 무효화된 세션은 사용할 수 없습니다.
  • 로그인·회원가입·매니저 관리·로그아웃·계정 찾기·비밀번호 변경 요청은 세션별 CSRF 토큰이 필요합니다. 기존 게시판·평가·운영 기능의 별도 CSRF 검사도 유지합니다.
  • 로그인 성공 시 세션 ID와 계정용 CSRF 토큰을 교체하고, 같은 계정/학교/접속지에서 10분 내 인증 실패가 5회 누적되면 해당 조합의 추가 로그인을 잠시 제한합니다.

5. 회원 프로필·거래 평가·매너온도

  • 상단 내 프로필/프로필 아이콘에서 본인 이름·학교·매너온도·받은 평가·판매글을 확인합니다.
  • 상품 상세의 판매자 카드에서 해당 회원의 공개 프로필과 다른 판매글을 확인합니다.
  • 판매글에는 서버가 실제 로그인 회원 ID를 저장합니다. 클라이언트가 보낸 다른 회원 ID로 작성자를 위조하거나 수정으로 소유자를 바꿀 수 없습니다.
  • 온도는 회원별 누적값입니다. A를 평가하면 A의 다른 판매글에도 같은 최신 온도가 보이지만 B/C의 온도는 바뀌지 않습니다.
  • 기본 36.5℃ / 최저 0℃ / 최고 99℃로 DB·서버·화면 게이지 기준을 통일했습니다.
  • 실제 거래 상대만 평가하고 중복 평가를 막으며, 별점과 GOOD/BAD 평가를 함께 집계합니다.
  • 관리자 화면의 좋아요·아쉬워요·별점 누적 집계와 실제 온도 증감을 표시합니다.
  • 별점 평가가 4~5점이면 좋아요, 1~2점이면 아쉬워요, 3점이면 보통으로 집계합니다.
  • 본인은 받은 후기 상세를 확인합니다. 공개 판매자 정보에는 전화·이메일·학번·비밀번호·자유 입력 후기 본문을 제공하지 않습니다.

판매자 연결다른 회원 판매글에도 평가가 적용된다는 문제판매글에 실제 작성 회원 ID 저장. 본인/거래 상대 확인 후 해당 회원에게만 평가 반영
판매자 표시목록마다 판매자 박스를 넣는 형태는 원하지 않음목록 박스는 제거하고, 상품 상세에 이름·학교·온도·별점·거래 통계를 표시
A/B/C 시연모든 예시가 같은 판매자처럼 보임시연판매자 A/B/C 준비. 기존 거래가 있는 글의 소유권은 유지하고 거래 없는 예시만 구분
본인 온도본인이 온도를 확인할 전용 화면 필요내 프로필에서 온도·받은 평가·판매글 확인. 판매자는 공개 프로필로 연결
관리자 평가별점 평가가 좋아요/아쉬워요 누적에 반영되지 않음GOOD/BAD와 별점 평가를 함께 집계. 4~5점/1~2점/3점 분류 및 실제 증감 표시
검색입력을 한 번에 지울 수 없음물품·게시글 등 검색 입력에 삭제 X 추가
약속 알림판매자에게 실제 약속 알림이 전달되는지 확인 필요앱 내부 알림과 실제 이메일 수신 검증 완료. 문자/알림톡 진행 상태는 상단 표에서 별도 확인

12. 회원·판매글·온도가 연결되는 방식

판매글을 등록할 때 화면에서 임의로 보낸 판매자 이름을 믿지 않고, 로그인한 회원 번호를 서버가 저장합니다. 예를 들어 판매자 A의 글 두 개는 모두 A의 프로필로 연결되고, B의 글은 B의 프로필로 연결됩니다.

거래가 완료된 후 실제 거래 상대만 평가할 수 있습니다. A가 받은 평가는 A의 회원 온도에 누적되므로 A의 여러 판매글에 같은 최신 온도가 보이는 것은 정상입니다. B/C의 판매글에 A의 변화가 나타나면 안 됩니다. 이 회원 간 분리와 중복 평가 방지를 검사했습니다.

초기 온도는 36.5℃, 범위는 0~99℃입니다. 콘텐츠 하트를 누르는 좋아요는 거래 매너 평가와 별개이므로 매너온도를 바꾸지 않습니다. 공개 프로필의 평가 수와 통계는 실제 기록을 집계하며, 후기가 없으면 빈 상태로 표시합니다.

14. 직접 확인하는 순서

  1. ZIP 전체를 새 폴더에 풀고 세사이트_모두실행.cmd를 실행합니다. 기존 데이터 폴더에 덮어쓰거나 schema.sql 전체를 실행하지 않습니다.
  2. 학생 화면에서 인하대학교 / 20261234 / campus1234!로 로그인합니다.
  3. 판매글 사진의 하트를 누르고 상단 좋아요 목록에 나타나는지 확인한 다음, 다시 눌러 취소합니다.
  4. 상품을 열어 상단 좋아요·닫기 버튼과 판매자 카드를 확인합니다. 카드에서 다른 판매글과 공개 프로필로 이동합니다.
  5. 커뮤니티에서 글을 열고 댓글을 작성합니다. 목록의 댓글 수·좋아요가 같은 줄에 표시되는지 확인합니다.
  6. 학교생활에서 실제 업체 세 곳과 지도 핀을 확인합니다. 각 업체의 지도 보기·좋아요 버튼이 나란히 있는지 확인합니다.
  7. 사장센터에서 owner_italy / campus1234!로 로그인해 운영 상태를 변경하고 학생 화면 반영을 확인합니다. 다른 회원의 가게를 수정할 수는 없습니다.
  8. 관리자 admin1 / campus1234!로 평가 누적 집계와 별점 기록을 확인합니다. 학생/사장 계정으로 관리자 API를 호출하면 거부됩니다.
  9. 실제 메일 기능은 회원에 등록된, 직접 받을 수 있는 이메일을 사용합니다. 공유 서버는 실제 SMTP 연결 상태이며 새 컴퓨터는 비공개 설정이 필요합니다.
  10. 문자/알림톡은 상단 상태 표와 외부 서비스 설정을 확인합니다. 시험 수신함에 표시된 모의 메일을 실제 외부 수신으로 혼동하지 않습니다.

15. 검증 범위와 보존한 데이터

  • 전체 Java 검사 85개 통과 결과는 최종 manifest에 기록했습니다. 문서만 바뀐 뒤 같은 검사를 반복 실행한 것처럼 추가 횟수를 주장하지 않습니다.
  • 계정 찾기·재설정과 이메일 약속 알림은 외부 네이버 받은메일함까지 확인했습니다. 실제 회원 비밀번호를 바꾸지 않고 격리된 시험 DB를 사용했습니다.
  • 카카오 주소 변환은 실제 키로 도로명/지번 검색을 확인했습니다. 지도 서비스는 주소 검색과 지도 표시의 역할을 구분합니다.
  • 기존 파일 DB는 백업 후 사용했습니다. 이전 거래·평가가 연결된 판매글의 회원을 임의로 바꾸지 않았습니다.
  • 실행 JAR과 소스가 같은 구현을 담는지, ZIP 무결성과 변경 파일 해시를 검사합니다. 비밀키·앱 비밀번호·실제 회원 DB는 ZIP에서 제외합니다.

16. 미포함 또는 별도 조건이 필요한 기능

항목현재 범위
