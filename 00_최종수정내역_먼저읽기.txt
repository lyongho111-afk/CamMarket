2. 관리자 학교 정보 CRUD
------------------------------------------------------------
- 관리자 → '학교 정보 관리'에서 조회·등록·수정·삭제를 제공합니다.
- 관리 항목: 학교명, 주소, 지역 표시, 위도·경도, 학교 인증용 이메일 도메인,
  학교 전경 사진, 약도 이미지.
- 이메일은 사용자 답변에 따라 '학생 인증용 도메인'으로 확정했습니다.
  대표 이메일 주소를 입력하는 필드가 아닙니다. 예: inha.edu,inha.ac.kr
- 기존 School.emailDomain을 사용하며 여러 도메인은 쉼표로 구분합니다.
- 좌표는 학교 기본 지도 중심에 반영하고, 전경/약도 이미지는 학교생활에서 표시합니다.
- 이미지는 관리자만 업로드할 수 있고 JPG/PNG, 파일당 5MB 이하입니다.
- 중복 이름과 오래된 수정 버전을 거절합니다.
- 회원·판매글·게시글·가게에서 참조하는 학교는 삭제할 수 없습니다.
- 초기 데이터 입력과 관리 화면 변경을 구분해, 초기화 코드가 관리자 수정/삭제를 다시 덮어쓰지 않도록 했습니다.
- 회원 서비스 대상은 아래 3개입니다. 이전 학교 6곳은 회원 선택에서 제외하되 기존 기록은 보존했습니다.
  새로 등록한 기타 학교는 관리 목록에는 나타나지만 회원가입 대상으로 자동 확장되지 않습니다.
  이는 서비스 대상을 3곳으로 확정한 요청에 따른 처리입니다.

관련: School.java, SchoolRepository.java, SchoolCatalogService.java,
      SchoolImages.java, CatalogController.java, CatalogSeed.java,
      portal-sites/admin/catalog.js, static/catalog.css

3. 관리자 업종 정보 CRUD 및 가게 화면 연동
------------------------------------------------------------
- 관리자 → '업종 정보 관리'에서 조회·등록·수정·삭제를 제공합니다.
- 초기 요청 업종 9개: 카페, 편의점, 중식, 양식, 디저트, 호프, 주점, 당구장, 탁구장.
- 기존 가게에서 이미 사용 중인 업종(예: 음식점)은 호환을 위해 함께 유지합니다.
- 업종 목록은 business_categories 테이블에서 조회합니다.
- 사장 회원가입과 사장센터 가게 등록·수정 화면을 DB 선택 목록에 연결했습니다.
- 서버에서도 등록된 업종인지 검사합니다. 사용 중인 업종은 삭제할 수 없습니다.
- 업종명을 바꾸면 기존 가게의 업종명도 같은 트랜잭션에서 수정하고 버전을 증가시킵니다.
- 기존 shops.busi_kind 문자열 컬럼을 유지했습니다. 새 업종을 추가할 때 소스를 고칠 필요가 없습니다.
- 다른 화면에서 변경한 업종은 화면 새로고침 후 선택 목록에 반영됩니다.

4. 회원 소속 학교별 서비스 분리
------------------------------------------------------------
서비스 대상:
  - 인하대학교
  - 인천대학교
  - 청운대학교 인천캠퍼스

회원가입·로그인:
- 학생 및 사장 가입 학교 목록은 위 3개 학교만 반환합니다.
- 회원은 기존 member.school_id에 소속을 저장합니다.
- 내부 캠퍼스 구분 코드 INHA/INU/CHUNGWOON을 학교 행에 저장하여 학교명 수정 후에도 ID 연결을 유지합니다.
- 대상 외 학교로 새 가입하거나 해당 학생 계정으로 로그인하는 요청은 거절합니다.

조회·검색·상세 권한:
- sales, board_posts, shops에 school_id를 연결했습니다.
- 학교 ID는 요청 JSON/검색 파라미터 대신 서버의 로그인 세션과 회원 DB에서 결정합니다.
- 판매글·게시글 등록 시 서버가 학교 ID를 저장합니다.
- 목록·검색·상세·댓글·거래·좋아요 조회/등록에 학교 범위를 적용합니다.
- 다른 학교 콘텐츠의 REST 주소나 기존 상세 화면 주소로 접근해도 같은 서비스 검사를 거칩니다.
- 기존 작성자/판매자/거래 참여자 권한 검사를 유지했습니다.
- 관리자는 기존 운영 권한대로 학교 전체 데이터를 관리합니다.
- 매니저는 담당 사장 회원의 학교를 따릅니다.
- 관리자 가게 사장 배정에서도 다른 학교 사장에게 배정하는 것을 막았습니다.
- 비회원의 기존 공개 기본 화면은 인하대 기준으로 유지합니다. 로그인하면 회원 소속 학교로 전환합니다.

같은 학번을 사용하는 다른 학교 회원:
- 기존 student.unisno가 전역 기본키여서 다른 학교의 동일 학번 가입이 충돌하던 부분을 수정했습니다.
- 기존 인하대 거래 식별자는 유지하고, 나머지 학교 회원은 내부적으로 고유 회원 ID를 사용합니다.
- 화면의 학번과 로그인 방식은 그대로 '학교+학번'입니다.
- 판매자 소유권, 구매자, 거래 참여자, 알림 수신자, 매너온도 연결에 내부 식별자를 일관되게 사용합니다.
- 다른 학교의 같은 학번 계정이 기존 회원의 거래나 온도를 가져갈 수 없게 했습니다.

화면·지도:
- 상단 학교 이름, 안내 문구, 새 판매글 기본 장소, 커뮤니티 표시를 회원 학교 정보로 바꿉니다.
- 학교생활 지도와 거래 장소 지도는 DB에 저장된 회원 학교 좌표를 사용합니다.
- 사장 가입 지도도 선택한 학교의 좌표로 이동합니다.
- 학교를 바꾸면 이전 가게 위치 선택을 다시 확인하도록 합니다.
- 공개 업체가 없는 학교는 다른 학교 업체를 대신 보여주지 않고 빈 목록을 표시합니다.

      StudentMemberLink.java, MarketMember.java, RatingSession.java,

5. 기존 데이터 연결 및 마이그레이션
------------------------------------------------------------
- 회원 ID로 판매글/게시글/가게의 소속 학교를 먼저 연결합니다.
- 기본 예시 게시글의 demo-student 작성 데이터는 원래의 인하대 예시 데이터로 연결합니다.
- 제공된 원본의 시연 판매자·가게 연결을 유지했습니다.
- 연결 근거가 없는 기존 행은 다른 학교로 임의 노출하지 않고 학교 미확인 상태로 둡니다.
- 기존 H2 DB용 추가 마이그레이션 파일:
  src/main/resources/campus-catalog-migration.sql
- 원본 ZIP의 schema.sql+data.sql에 마이그레이션을 적용하는 H2 실행 검증을 통과했습니다.
- 기존 DB를 유지해 업그레이드하려면 먼저 백업 후 추가 SQL을 적용하고,
  기존 DB에서는 전체 schema/data 재초기화를 끄고 JPA ddl-auto=update로 시작해야 합니다.
  기존 DB가 아닌 새 압축본의 기본 실행은 포함된 초기 스키마로 시작합니다.
- 별도 MySQL 실서버 업그레이드는 이번에 검증하지 않았습니다.

8. 실행 및 확인 주소
------------------------------------------------------------
압축을 새 폴더에 모두 푼 뒤 '세사이트_모두실행.cmd'를 실행하세요.
다른 서버가 이미 8080~8082를 사용 중이면 먼저 종료해야 합니다.

압축본 기본 주소:
  학생: http://127.0.0.1:8080/
  관리자: http://127.0.0.1:8080/admin/
  사장·매니저: http://127.0.0.1:8080/owner/
  내 정보·비밀번호 변경: http://127.0.0.1:8080/account.html

현재 이번 수정본의 별도 검증 주소(이 컴퓨터에서만):
  학생: http://127.0.0.1:8093/
  관리자: http://127.0.0.1:8093/admin/
  사장: http://127.0.0.1:8093/owner/

현재 8093 검증 서버에만 만든 테스트 계정:
  학교: 위 대상 3곳 중 선택 / 학번: 20269501 / 비밀번호: campus1234!
  세 학교 모두 같은 학번으로 각각 등록했습니다. 각 계정의 학교별 검증 글이 있습니다.
  관리자: admin1 / 사장: owner1 / 비밀번호: campus1234!
  새로 압축을 풀어 일반 실행한 DB에는 이번 검증용 20269501 계정을 자동 생성하지 않습니다.
  기존 기본 학생 시연 계정은 인하대학교 / 20261234 / campus1234!입니다.

DB·외부 연동 상태:
- 원본 기본 DB는 H2 메모리 방식이며 이번에도 유지했습니다. 일반 재실행 시 데이터가 초기화됩니다.
  관리자 화면에서 등록한 내용을 재시작 후에도 유지하려면 영구 DB 구성으로 별도 전환해야 합니다.
- ZIP에는 사용자 DB 백업, 개인 설정 local.env.cmd, 실제 키/비밀번호, 업로드 파일과 로그를 넣지 않았습니다.
- 주소 자동 변환용 API 키, SMTP, 문자/카카오의 실제 외부 발송 설정·최종 수신 확인은 이번 작업 범위에서 완료하지 않았습니다.
- 학교 전경/약도는 관리자 업로드 후 표시됩니다. 제공되지 않은 실제 학교 사진을 임의로 만들어 넣지 않았습니다.
