4. DB 반영 방식과 기존 DB 사용

• AdditionalCampusShopsSeed.java가 서버 초기 데이터 준비 후 실행됩니다.
• campus-shops-20261106.json의 11곳을 읽어 회원·가게·학교를 연결합니다.
• catalog_meta의 ‘additional-campus-shops-20261106-v1’ 표시로 중복 등록을 방지합니다.
• 이미 반영된 DB에서는 재시작해도 계정을 다시 만들거나 사장센터에서 수정한 운영 상태를 되돌리지 않습니다.
• 가게 이름·주소가 기존 다른 소유자/학교와 겹치거나 사장 아이디가 이미 사용 중이면 임의로 덮어쓰지 않고 중단합니다.
• 실제 서비스의 일반 사장 회원가입은 기존처럼 관리자 승인 절차를 유지합니다. 이번 목록만 사용자가 추가를 요청한 공개 시연 가게로 등록했습니다.
• 새 사장 계정의 이메일은 example.invalid, 사업자번호는 DEMO 시연 식별자입니다. 실제 가게 대표자의 개인정보를 추측해 입력하지 않았습니다.
• 알림 수신은 새 계정 모두 꺼져 있어 이 작업으로 실제 이메일·문자·카카오 메시지가 발송되지 않습니다.

기존 파일 DB를 사용하는 경우:
1) 서버를 종료한 상태에서 기존 DB를 먼저 백업합니다.
2) 수정된 소스 또는 app/campus-remarket.jar를 적용합니다.
3) 기존 datasource 경로를 그대로 사용하고 spring.sql.init.mode=never, spring.jpa.hibernate.ddl-auto=none을 유지합니다.
4) 초기 시연 데이터 기능을 꺼 둔 환경은 campus.shops.seed-campus-20261106=true를 추가해 이번 11곳만 반영할 수 있습니다.
5) schema.sql/data.sql 전체를 기존 DB에 다시 실행하지 않습니다. 기존 DB를 메모리 DB로 전환할 필요도 없습니다.
